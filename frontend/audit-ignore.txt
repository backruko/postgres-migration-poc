# 画面の依存（npm audit）で、見送ると決めた脆弱性の一覧。CI の「依存関係の既知の脆弱性（npm audit）」が読む
# （scripts/audit-check.mjs。手元では frontend で npm run audit:check）。
#
# ■ まず上げる。見送りは最後の手段
#   止まったら、表示された勧告の修正版まで package.json の版を上げて npm install し、package-lock.json もコミットする。
#   直接の依存でないもの（間接の依存）は、package.json の "overrides" で修正版を指定する。
#   見送るのは、すぐには上げられない理由があるときだけ（大きな版の変更で画面を直す必要がある・修正版がまだ無い など）。
#
# ■ 書き方: 1 行に 1 つ。勧告の ID（GHSA-xxxx-xxxx-xxxx）と、# のあとに理由
#   ID は CI のログの勧告の行（https://github.com/advisories/GHSA-… の末尾）から写す。理由の無い行・ID の形の誤りは、
#   CI を赤にする。理由には、なぜ今は危なくないか・いつ・何をして消すか（見直す日）・決めた人を書く。
#
# ■ 例（行の頭の「# 」を外すと有効になる）
#   ・使っていない機能の脆弱性で、修正版が大きな版の変更のとき:
# GHSA-xxxx-xxxx-xxxx  # SSR の hydration だけの問題。この画面は SSR を使わない。React Router 7 への移行（見直し: 2027-01-31）で消す。決めた人: 山田
#   ・修正版がまだ出ていないとき:
# GHSA-yyyy-yyyy-yyyy  # 修正版がまだ無い。影響する「〇〇」の部品は画面で使っていない。修正版が出たら上げて消す（見直し: 2026-12-15）。決めた人: 佐藤
#
# ■ 消す
#   勧告が出なくなった行（直った・取り下げられた）は、CI のログに ::warning:: で知らせるので消す。見直す日を過ぎた行も見直す。
#   high 未満（moderate など）は止めないので、ここに書く必要はない。
