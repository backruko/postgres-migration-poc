# mfa 連携アダプター（並行稼働用・使い捨て）

業務オーケストレーション（新しいシステム）から **これから始める作業の時刻表** を読み、旧来の仕組みのための 2 つのファイルを書きます。

| ファイル | 中身 | 使い道 |
|---|---|---|
| `mfa.txt` | 予定の開始の時刻に「始めて」と知らせる `Msg` の行（設定すれば同じ時刻の `Mplay` の行も） | mfa が読む |
| `access_check.csv` | 日付・顧客コード・業務コード・予定名・開始（HH:MM）・状態（未処理 / リリース済） | Access に人が入力した内容と見比べる |

どちらも **Shift_JIS（CP932）・改行 CRLF**。`mfa.txt` の行はいまのファイルと同じ形です:

```
26/11/20 15:30 Mplay  Repeat E:\sound\gm\e_警報.wav     ← 設定の sound があるときだけ
26/11/20 15:30 Msg    【ABCD】月次ファイル送信を【17時まで】に実施してください
```

## 決まり（新しいシステムが決める。アダプターは書き写すだけ）

- 載るのは、分類が **不定期・スペシャル** の予定テンプレートで、**「開始時刻に知らせる」がオン** のもの、臨時に追加した予定、
  かつ **まだ始めていないオーダー（未リリース・リリース済）**。取消・保留・作業中・完了は載らない
- 時刻は **予定の開始**。締切は文面に入れる（同じ日なら「11時」「11:30」、翌日なら「翌日9時」、それより後なら「11/18 9時」）
- このアダプターは新しいシステムの外にあり、読み取り専用の API キーで `GET /api/ops/schedule-feed` を読むだけ。並行稼働が終わり、
  mfa を止めたら、このフォルダーごと消す

## 準備（1 回だけ）

1. Windows サーバーに Python 3.10 以上を入れる（追加のパッケージは要らない）
2. このフォルダーを置く（例: `D:\ops_adapter\`）
3. 新しいシステムの「職員」画面で、ロール「システム連携（読み取り）」のアカウントを作り、API キーを発行する
4. キーを環境変数 `OPS_API_KEY`（タスクを実行するユーザーの環境変数）か、別のファイル（`key_file`）に置く
5. `mfa_adapter.ini.example` を `mfa_adapter.ini` に写し、`base_url`・`dir` などを直す。
   **並行稼働の間は `dir` を mfa が読む本物のファイルとは別のフォルダーにする**（新旧を見比べるため）
6. 試す: `run_mfa_sync.bat --dry-run`（書かずに、書く内容を画面に出す）→ `run_mfa_sync.bat`

## 毎晩の実行（タスク スケジューラー）

- 操作: `D:\ops_adapter\run_mfa_sync.bat`、開始: 毎日 02:00
- 昼間に予定が変わったときは、同じバッチを手で実行すれば書き直す（ファイルは丸ごと置き換わる）
- ログ: `logs\mfa_sync.log`（件数・期間・警告）。写し: `archive_dir` に日時つき（`archive_keep_days` 日で消える）

## 終了コード

| コード | 意味 | 書いたか |
|---|---|---|
| 0 | 書いた（dry-run のときは表示だけ） | 書いた |
| 2 | 設定ファイル・API キーの誤り | 書いていない |
| 3 | API に失敗（つながらない・キーが違う 401 など） | 書いていない（前のファイルのまま） |
| 4 | ファイルを書けない | 前のファイルのまま |
| 5 | 時刻表が上限で切れた（`days` を小さくする） | 書いていない |
| 6 | 切り替えのあと: Excel の txt（`[cutover] excel_file`）を読めない | 書いていない（スクリプトの行を落とさないため） |
| 7 | 切り替えのあと: mfa に読み直させられなかった（`MFA.exe /R` の失敗・静かな分が無い） | 書いた。**mfa は前のファイルのまま**（手で `MFA.exe /R`） |

API に失敗したときは何も書かないので、mfa は前の晩のファイルのまま動きます。

## 切り替えのあと（`[cutover]`。[deploy/GO-LIVE.md](../../deploy/GO-LIVE.md) の J.）

並行稼働の間は `[cutover] enabled = false` のままです（上のとおり `[output]` にだけ書く）。承認と切り替えの準備（J-1・J-2）の
あとで `true` にすると、毎晩の実行がさらに次のことをします（2026-11-17 の計画。設計書の「Cut-over: mfa rings from the new file」）。

1. **組み合わせる（M.1）**: 運用の担当が Excel から書き出して置く txt（`excel_file`）を読み、mfa が読む本物のファイル
   （`live_file`）を作る
   - Excel の知らせ（Msg）のうち、新しいシステムも出すもの（同じ作業・`[parity] tolerance_minutes` 分以内。照合と同じ決まりと
     同じ別名の表）は、新しいシステムの知らせに置き換える。その直前の同じ分の音（Mplay）は、新しい知らせの時刻へ一緒に移す
     （緊急度と鳴らす機器が変わらない）
   - 新しいシステムが出さない Excel の知らせは、音つきのまま残す（鳴らないより、2 回鳴るほうが安全）。照合の「欠け」に出るので、
     テンプレートを直す
   - 新しいシステムだけが出す知らせは、`[mfa] sound` の既定の音
   - ほかの行（**Shell のスクリプト**・知らせの無い音・ほかの命令・日時を読めない行）は、そのまま写す。いまより前の行は書かない
2. **読み直させる（M.2）**: 書いたあと、前後 `quiet_minutes` 分に行の無い分まで待って（最長 `max_wait_minutes` 分）
   `mfa_exe reload_args`（`MFA.exe /R`）を動かす。`mfa_exe` が空なら読み直さない（手で）。`MFA.exe` が 60 秒たっても終わらない
   ときは、mfa そのものかもしれないので止めずに警告だけ出す（J-1 で、どう動くかを確かめる）

`[output]` の新しいシステムだけのファイルと、その写し（`mfa_YYYYMMDD_HHMMSS.txt`）は、切り替えの前と同じに書きます。照合
（`parity_report.py`）はこれと Excel の txt（`[parity] legacy_file` を `excel_file` と同じにする）を見比べるので、新しいシステムが
出さない知らせは切り替えのあとも「欠け」として出ます。本物のファイルの写しは `live_mfa_YYYYMMDD_HHMMSS.txt`（照合は拾わない）。

`--dry-run` は組み合わせた中身と、読み直させる時刻を表示し、何も書かず、mfa も動かしません（J-2 の見比べに使う）。ログには、
置き換えた知らせ・Excel のまま残した知らせ・新しいシステムだけの知らせ・そのまま写した行（命令ごと）の数が出ます。

## 新旧の照合（`parity_report.py`）

並行稼働の 14 日間、mfa はいままでの（旧の）`mfa.txt` を読み続けます。`parity_report.py` は、旧のファイルとアダプターが書いた新の
ファイルを見比べ、**旧の `Msg` の行すべてに、同じ作業で開始の差が 3 分以内の新の行があるか** を確かめます（合格の条件）。

旧の `mfa.txt` は、リマインダーの Excel（開始の時刻が決まった作業・リマインダーの名前・.vbs のスクリプト・音）から **月に 1 回**
作られます。そのため人が見比べるのは **初日の前に月全体を 1 回**（下の「月全体を 1 回で」）と、**終わりのまとめ** だけです
（2026-11-17 の決定。手順は `deploy/GO-LIVE.md` の I.）。毎晩のタスクは、その晩の写しと結果を残すために動かし続けます。

**毎晩（タスク スケジューラー、アダプターのすぐ後）:** 操作 `D:\ops_adapter\run_mfa_parity.bat`、開始 毎日 **02:15**。
旧の `mfa.txt`（設定の `[parity] legacy_file`）を、アダプターの最新の写しの隣に **同じ日時の名前** で写し
（`archive\legacy_mfa_20261117_020000.txt` ↔ `archive\mfa_20261117_020000.txt`）、見比べて `[parity] out_dir` に結果を書きます。
要約は `logs\mfa_parity.log` に追記されます。

- 昼間にもう一度実行しても、その晩の旧の写しは置き換えません（夜の時点の旧のファイルを残すため）
- アダプターの最新の写しが 26 時間より古いとき（昨夜アダプターが動かなかった）は、何も見比べず終了コード 2
- 旧の `mfa.txt` が作り直される日（ふつうは月に 1 回）は、作り直しが終わった後に動くよう、その晩だけ開始の時刻をずらすか、
  翌日に月全体の照合をもう一度行う

**並行稼働の終わりに（承認の記録）:**

```
run_mfa_parity.bat --rollup --from 2026-11-17 --to 2026-11-30
```

期間の毎日を **いまの別名の表で見比べ直し**（途中で足した別名も前の晩に効く）、次の 3 つを書きます:
`parity_rollup_<始め>_<終わり>.csv`（1 日 1 行: 判定・種類ごとの件数・使った写し）、`…_details.csv`（一致以外の行をすべて、
日付つきで）、`…_summary.txt`（合計と判定）。日ごとの結果も書き直します。各日は **その日の最初の組（夜の定時の実行）** を使います。
**照合の組が無い日（旧の写しが無い晩）も NG** です（承認には 14 日すべてが要るため）。

**2 つのファイルを指定して 1 回だけ:**

```
python parity_report.py --legacy D:\mfa\mfa.txt --new D:\ops_adapter\archive\mfa_20261116_020000.txt --out D:\ops_adapter\parity --aliases parity_aliases.csv
```

- 見比べる時間帯: 新のファイルを作った時刻から 24 時間（アーカイブの名前の日時。1 回だけのときは `--window-start` `--hours` で
  変えられる）。**月全体を 1 回で**: アダプターの写しは 30 日先まであるので（設定の `days`）、`--hours 720` で 30 日分をまとめて
  見比べられる（並行稼働の初日の前。結果の CSV に全日の行が日付つきで並ぶ）。その晩のファイルが受け持つ 1 日だけを見るので、旧と新で何日先まで書いているかが違っても構いません
- 同じ作業 = `【顧客コード】` と、「を【」「を実施」より前の作業名が同じ（全角・半角と空白の違い、「※」から後は無視）
- 1 つの旧の行には 1 つの新の行だけを対応させます（同じ日に同じ作業が 2 回あれば、2 つの新の行が要る）
- 結果: `parity_YYYYMMDD_HHMM.csv`（1 行ずつの判定。UTF-8 BOM つきで Excel でそのまま開ける）と `…_summary.txt`（件数と判定）

| 種類 | 判定 | 意味 |
|---|---|---|
| 一致 | OK | 同じ作業・開始の差 3 分以内（締切の言い方が違えば備考に「参考」） |
| 時刻ずれ | **NG** | 同じ日に同じ作業があるが、3 分を超えてずれている |
| 欠け（旧だけ） | **NG** | 新に対応する行が無い。同じ顧客・同じ時刻の新の行があれば備考に候補を出す |
| 余り（新だけ） | 要確認 | 新にだけある。旧の入力漏れか、テンプレートの設定（分類・「開始時刻に知らせる」）の違い。NG にはしない |
| 要確認（音だけ） | 要確認 | 同じ分に `Msg` の無い `Mplay` の行 |
| 読めない行 | 要確認 | 「YY/MM/DD HH:MM 命令 引数」の形でない行 |
| 対象外 | 対象外 | `Shell` の行（スクリプトの自動実行）。新しいシステムは書かず、mfa がそのまま動かす |

**別名の表**（`parity_aliases.csv`、任意）: 同じ作業なのに旧と新で名前が違うとき、旧の名前を新の名前に読み替えます。
見出しの行のあとに `旧の顧客,旧の作業,新の顧客,新の作業`（新の顧客が空なら旧と同じ）。Excel で保存した CSV（CP932）でも
UTF-8 でも読めます。欠けの備考に出る候補を見て、名前の違いだけならこの表に足します。設定の `aliases` の表がまだ無ければ、
別名なしとして見比べます。

終了コード: **0** = OK（NG なし）、**1** = NG あり（まとめでは照合の無い日があるときも）、**2** = 入力の誤り（ファイルが無い・
読めない・別名の表や設定の誤り・アダプターの昨夜の写しが無い）。

写しは `archive_keep_days`（見本では 60 日）で消えるので、14 日の並行稼働のまとめには足ります。

Access 側は自動で見比べません（Access には書き出しの機能が無いため）。QA が `access_check.csv` を Excel で開き、Access の画面と
目で見比べます。

## 注意

- CP932 に無い文字（例: 〜）は見た目の同じ文字に直します。それでも書けない文字は「?」にし、ログに警告を残します
- 知らせる作業が 0 件のときも空のファイルを書き、ログに警告を残します（分類・「開始時刻に知らせる」の設定を確かめる）
