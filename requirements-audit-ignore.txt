# サーバーの依存（pip-audit）で、見送ると決めた脆弱性の一覧。scripts/audit_check.py（CI の「依存関係の既知の脆弱性
# （pip-audit）」。手元ではリポジトリのルートで python -m scripts.audit_check）が読み、1 行ごとに pip-audit --ignore-vuln <ID>
# を付ける（requirements.txt・requirements-dev.txt のすべてが対象。重さを問わず、1 つでもあれば止める）。
#
# ■ まず上げる。見送りは最後の手段
#   止まったら、表示された Fix Versions まで requirements.txt（または requirements-dev.txt）の版を上げ、テストを通してコミットする。
#   間接の依存も、ここでは版を書いて並べているので同じように上げる（上げた版で pip check が通ること）。
#   見送るのは、すぐには上げられない理由があるときだけ（修正版がまだ無い・修正版がほかの依存と合わない など）。
#
# ■ 書き方: 1 行に 1 つ。脆弱性の ID と、# のあとに理由
#   ID は CI のログの表の ID 列から写す（CVE-…・GHSA-…・PYSEC-… のどれでもよい。pip-audit は別名でも合わせる）。
#   理由の無い行は CI を赤にする。理由には、なぜ今は危なくないか・いつ・何をして消すか（見直す日）・決めた人を書く。
#
# ■ 例（行の頭の「# 」を外すと有効になる）
#   ・使っていない機能の脆弱性で、修正版がほかの依存と合わないとき:
# CVE-2026-0000000  # 影響するのは △△ の XML 読み込みだけで、このアプリは使わない。修正版は FastAPI の次の版と合わせて上げる（見直し: 2026-12-31）。決めた人: 山田
#   ・修正版がまだ出ていないとき:
# GHSA-xxxx-xxxx-xxxx  # 修正版がまだ無い。外から届く入力では起きない（社内の管理画面だけ）。修正版が出たら上げて消す（見直し: 2026-12-15）。決めた人: 佐藤
#
# ■ 消す
#   版を上げて直ったら、その行を消す（pip-audit は使われなかった行を知らせないので、見直す日に必ず確かめる）。
